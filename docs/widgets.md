# 桌面小组件使用与扩展

本文介绍桌面小组件的使用与扩展。

## 一个桌面

当前场景、当前分组只有一个桌面网格。网址与图标文件夹占 1×1，仍使用原来的图标、菜单、文件夹和批量操作；组件是独立数据实体，不会伪装成网站。

点击网格加号，或右键桌面空白处，打开同一个添加面板。面板显示当前分组，默认聚焦网址；粘贴合法 HTTP(S) 网址可直接回车，以主机名补默认名称，也可自行命名。切换“小组件”可在同一面板选择组件。书签批量导入、批量网址与高级快捷方式沿用原入口。只有一个分组时隐藏分组标签，仍可用加号新建分组；第二组出现后显示切换标签，启用场景后当前场景始终可见。选择便笺、清单、常用链接、倒计日或时钟后，先填写内容，再点击“添加”；取消不会留下空卡片。卡片直接展示内容，清单可直接勾选。通过卡片右上角“⋯”、右键或长按内容区打开编辑与删除菜单；键盘可用 Shift＋F10 打开菜单、方向键选择、Esc 关闭。删除和恢复不显示通知；可用 Ctrl/Cmd＋Z，或在组件管理中选择“撤销删除”。撤销依赖删除后的工作区版本和原空位，避免覆盖后续修改。

编辑器先展示内容，“尺寸与位置”和恢复数据按需展开。取消、关闭与 Esc 一致舍弃当前草稿，保存期间暂停关闭与重复提交；保存失败时保留表单并可重试。错误在相关表单内显示；无表单时仅显示可关闭的短暂角落提示，不占桌面布局。清单输入事项后按 Enter 可继续添加，新增和删除行会将焦点移到可继续操作的位置。

## 大小与定位

- 设置有 1×1、2×1、1×2、2×2、4×2 快选，也可输入自定义整数行列。高度 1–12，宽度不能超过当前分组的桌面列数，起始行 1–512。
- 设置 → 快捷方式布局中的“桌面列数”支持 1–12。点击“应用列数并整理”是显式重新排列操作，不改变组件大小；若列数小于现有组件宽度则拒绝保存，需要先缩小该组件。
- 拖动组件标题前的手柄即可跟手移动。占用位置会自动腾位：被碰到的图标或小组件按原尺寸滑到附近空位，其他位置尽量保留。预览与松开保存使用同一份纯布局方案；拖动过程中不写入数据，取消会把整组预览还原。
- 网址可拖到空位，拖到普通图标上只排序，不使用计时或 Shift 合并。拖到已有图标文件夹上立即显示加入预览，松开才加入；取消不会写入。要建文件夹，请进入“选择网站”，选择至少两个普通 HTTP(S) 网站后点击“新建文件夹”。文件夹内部、SSH、工具和组件不适用。拖到小组件上也会自动腾位，文件夹的子项关系保持不变。图标文件夹内的拖动与提取继续走现有文件夹逻辑。
- 组件标题手柄可用方向键，网址可用 Alt＋方向键。尺寸/坐标表单可替代拖动。触屏可拖动标题手柄，内容区保留滚动与长按菜单；Esc、指针取消、失去焦点或窗口投影变化会取消拖动。落点按原抓取位置对齐，桌面边缘会按组件宽度吸附，移出桌面或视口则取消。拖动中收到其他位置的工作区更新会取消当前手势，避免覆盖新数据。
- 未受影响的空位不会因移动或删除自动压紧。位置预览使用平移和短缓动动画，落下时平滑归位；系统减少动态效果时停用这些动画。应用桌面列数时会整理位置；网站数组顺序不因网格位置写入而变化。
- 窄窗口只改变显示投影，绝不因 ResizeObserver 写入坐标或改小存储尺寸。投影模式禁用指针定位，避免预览坐标与逻辑坐标混淆；可通过设置或键盘明确修改逻辑位置。恢复宽窗口后显示保存的原布局。
- DOM 顺序跟随当前显示的行列顺序；保留原生 Tab 行为。卡片内容可滚动，设置和组件库使用原生模态 dialog。

旧布局迁移保留原 6 列；新分组初次布局参考既有列数设置，没有固定列数时默认 6 列。一旦保存，列数属于该分组；之后在设置的分组桌面列数中显式修改。默认“每行个数”是未单独保存布局的分组所用的初始值（多场景下按场景保存），不会覆盖已有分组坐标；分组“桌面列数”优先，应用时会整理该分组。

## 用户注册真正的组合组件

打开“设置 → 组件管理 → 注册组合组件”（添加面板也有组件管理入口）。注册类型后，回到添加面板，在预览卡片点击“添加”。注销定义也在组件管理中，须先删除全部实例。注册不会自动创建实例，实例数据互相独立。以下示例可以直接粘贴；界面也提供完整示例。

```json
{
  "id": "my.project",
  "title": "项目进展",
  "kind": "composite",
  "size": { "w": 2, "h": 2 },
  "fields": [
    { "key": "title", "label": "项目", "type": "text" },
    { "key": "count", "label": "已完成", "type": "number" },
    { "key": "items", "label": "待办", "type": "list" },
    { "key": "due", "label": "截止日", "type": "date" },
    { "key": "progress", "label": "进度", "type": "progress" },
    { "key": "link", "label": "项目链接", "type": "link" }
  ],
  "blocks": [
    { "type": "text", "field": "title" },
    { "type": "number", "field": "count", "label": "已完成" },
    { "type": "list", "field": "items" },
    { "type": "date", "field": "due", "label": "截止" },
    { "type": "progress", "field": "progress" },
    { "type": "link", "field": "link" }
  ],
  "defaults": {
    "title": "我的项目",
    "count": 3,
    "items": ["整理资料", "完成设计"],
    "due": "2026-12-31",
    "progress": 30,
    "link": { "label": "项目文档", "url": "https://example.com/" }
  }
}
```

`fields` 定义数据与设置表单，`blocks` 按顺序声明内容。可以重复引用字段、调整顺序或选择其中一部分展示，不受四种旧模板布局限制。文本保留换行，数字必须有限，列表为字符串数组，日期为真实 `YYYY-MM-DD` 或空串，进度为 0–100，链接为 `{label,url}`。链接只允许 HTTP/HTTPS 且禁止携带用户名和密码；空链接不生成可点击元素。

类型 ID 以小写字母开头，只允许小写字母、数字、点和连字符，最长 64 字符。字段 key 以小写字母开头，后续可含字母、数字和下划线，最长 40 字符，禁止原型相关保留名。字段与内容块类型必须匹配。类型最多 24 个，每个组合最多 24 个字段、32 个内容块，全局实例最多 128 个，列表/清单/链接最多 40 项，文本最多 8000 字符。状态 UTF-8 上限为 256000 字节。注销定义前必须移除所有分组中的该类型实例。

旧版 note/checklist/links/countdown 定义仍可读取、重复实例化，不会被强制转换为组合定义。用户输入只作为数据：不接受脚本、HTML、iframe 或远程模块。未知类型读取为惰性恢复卡，不执行代码。

## 本地 renderer registry

`lib/widget-model.js` 提供 `registerRenderer(kind, renderer)`；`lib/widget-renderers.js` 为五种内置类型和组合型注册渲染器。核心桌面只调用注册接口，没有根据组件类型选择渲染的分支。

新增受信任本地类型时，在随扩展打包的脚本内注册，并在 home、popup 和 background 的模型之后加载同一脚本，将文件加入 `scripts/release-files.json`；无需修改桌面核心的类型分支。脚本初始化不能依赖 DOM，DOM 操作放到 render/edit 回调中。最小示例：

```js
OpenTabWidgetModel.registerRenderer('metric', {
  title: '计数',
  sizes: [[1, 1], [2, 1]],
  customSizes: true,
  size: { w: 2, h: 1 },
  defaults: { value: 0 },
  validate(raw) {
    if (!raw || typeof raw !== 'object' || Array.isArray(raw)
      || Object.keys(raw).some(key => key !== 'value')
      || !Number.isFinite(raw.value)) throw new TypeError('INVALID_WIDGET_DATA');
    return { value: raw.value };
  },
  render({ body, el, data }) {
    body.append(el('p', String(data.value)));
    return () => {}; // 定时器/订阅等资源的清理函数
  },
  edit(c) {
    const value = c.field('计数', c.data.value, 'number', { step: 'any', required: true });
    return () => ({ value: Number(value.value) });
  },
  cleanup(dispose) { if (typeof dispose === 'function') dispose(); }
});
```

此接口会加入 `local.metric` 类型，支持尺寸、默认数据、校验、渲染、编辑和清理。无须在 BUILTINS/KINDS 手工增添类型。若仅支持列举尺寸，设置 `customSizes: false`；默认尺寸也应列入 sizes。本地源码受信任，renderer 接口不是第三方代码沙箱。另一设备缺少该本地类型时保留其实例数据，显示恢复提示。

## 所有权、迁移与恢复

存储键仍为 `widgetWorkspace`，采用版本 2 JSON 字符串，包含 `definitions`、`widgets`、`pages`。组件的 `groupId` 是分组引用，场景由 `folders[].sceneId` 推导；不复制场景内容。pages 存储分组列数及网站 ID/坐标引用，网站内容仍只有原来的 icons 记录。

读取旧版本 1 时，仅给旧实例增加默认主页 `folder-home` 引用，保留 ID、定义、数据、尺寸和坐标。在共享 workspace 锁内一次写入新版状态和 `opentab.widgetMigrationBackup` 原文恢复记录。再次加载版本 2 不重复迁移或复制。若用户恢复了另一份版本 1 备份，会追加原文恢复记录，原记录不覆盖。配额不足/解析失败时原子写入失败，保留旧原文，不删资产腾空间。

分组删除的“移动”/“一起删除”会与组件变动一同提交，撤销也包含组件。分组跨场景移动依赖不变的分组 ID；场景归档/恢复只改变可见性，实例与布局保留。普通分组删除如遇到并发新增组件，协调器拒绝未处理组件的删除事务。

完整备份、快照和同步沿用既有入口，主状态含定义、所有分组实例和布局。恢复旧备份若没有 widgetWorkspace 字段，会保留本地数据并改成明确的待恢复引用；组件库“未找到原分组的组件”可移回当前分组，防止凭同名 ID 接到无关备份分组。远端同步遗漏本地恢复场景或分组时保留其实例；同 ID 定义/实例存在不兼容冲突会拒绝，交由既有同步恢复入口处理。远端没有组件字段时不主动清空本地组件。

未知类型可以导出原数据；缺失自定义定义可重新注册同 ID 定义恢复显示，缺少本地 renderer 时需安装包含该类型的扩展源码。畸形状态或未知存储版本不会被自动覆盖，可在组件管理中导出恢复数据与当前弹窗草稿，再重新读取或通过有效完整备份恢复。

所有组件编辑使用既有 `OpenTabWorkspace.commit` 与同一 Web Lock，检查原字符串、workspace epoch、目标场景/分组、当前视图代数和网址成员引用。整个组件状态是冲突单位：不同分组同时编辑也可能冲突，不做不可靠的自动覆盖。编辑中或写入失败时保留设置/注册/列数草稿，明确关闭或取消会舍弃；打开弹窗或有草稿时阻止普通分组切换。冲突后先导出，再使用明确标注的“舍弃设置和注册草稿并重新读取”。普通写入失败可以重试原草稿。保存期间收到的存储通知会延后处理，避免漏掉紧随本次提交的外部改动。

同步容量由 Chrome 的既有配额限制，256KB 本地上限不是云端可用容量承诺；超额走原有失败提示，本地数据保留。组件代码没有新增网络请求、权限或 CSP 放宽。时钟只使用本机 Intl，链接仅在点击时打开。

## 验证

`npm test` 包含布局模型与安装态组件浏览器回归。`HEADLESS=false node tests/widgets.test.mjs --web-fixture` 可在禁止安装扩展的开发环境中验证同一套页面、渲染器和协调器，使用独立的 Chrome 存储适配器；这不能替代安装态扩展 E2E。该适配器与测试页面不进入发布包。

每次布局拖放是一次事务，可在桌面按 Ctrl/Cmd＋Z 撤销；整组受影响的网站和组件坐标一起恢复。其他分组的新数据保留；当前分组成员或布局已被其他标签页修改时，旧撤销被拒绝。输入框内保留文字撤销。布局与注册草稿分别保留在各自设置入口，需明确取消/舍弃才能换组；发生冲突时通过组件管理导出草稿与原数据，再明确重新读取。升级与刷新不会自动整理现有桌面。
